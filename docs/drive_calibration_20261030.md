# 2026-10-30 주행 실측 인계

사용자가 기존 시험에서 확인한 결과다. 이번 세션에서 같은 명령으로 재측정한 값은 아니다.

| 동작 | 기존 시험 명령 (왼쪽 %, 오른쪽 %, ms) | 사용자 확인 결과 |
|---|---|---|
| 전진 | `-70 70 650` | 40 cm |
| 좌회전 | `50 50 480` | 90도 |

## 명령 해석과 적용 범위

- 명령 형식은 `firmware/motor_test/motor_test.ino`와 일치한다.
  실제 시험 당시 업로드한 스케치가 이 파일과 같은 버전인지는 별도 확인이 필요하다.
- 저장소의 motor_test는 10 ms마다 출력을 1%씩 올리고 내린다.
  지정 시간은 명령을 받은 때부터 세며, 시간이 끝나면 감속을 시작한다.
  따라서 `650`은 전체 이동이 정확히 650 ms 후 끝난다는 뜻이 아니다.
  정지 상태에서 시작했다면 목표 70%에 도달하기 전에 감속을 시작할 수도 있다.
- 현재 통합 임무는 `mega_sensor_controller`의 `$DRV` 속도 제어와 엔코더 위치를 사용한다.
  전진 0.40 m, 이웃 칸 방향으로 회전하며 이 시험의 출력 비율·시간을 직접 사용하지 않는다.
- 현재 펌웨어는 왼쪽 모터 방향 반전을 내부에서 적용한다. 시험 명령의 부호를 그대로
  현재 `$DRV`나 `$PWM`에 옮기면 같은 방향의 동작을 보장하지 않는다.
- 현재 `$PWM`은 -255~255 duty 단위이며 배선 확인용이다. 속도 제어 모드의
  엔코더 역방향·막힘 감시를 거치지 않으므로 자율 임무의 대체 주행 명령으로 사용하지 않는다.
- 이 기록만으로 속도 제어 이득·바퀴 치수·최소 속도·임무 주행 시간을 바꾸지 않는다.
  제어 방식 변경은 담당 1과 조원 A에게 공유하고 기존 0.3초 정지·고장 감시를 유지한다.

## 최근 통합 시험과 구분

Pi 로그 `mission1_20261030_232801.log`에서 잠깐 DRIVE 후 앞 `(9,2)`와 왼쪽 `(8,1)`이
막힌 칸으로 표시돼 STUCK으로 전환됐다. 주행 출력이 부족해서 정지한 것으로 확정하지 않는다.
종료 시 mega_bridge_node의 rclpy 예외도 기록됐으며, 종료 후 제어 노드와 Mega 포트 사용이
없음을 확인했다. 실제 바닥 주행 성공 여부는 아직 검증되지 않았다.
